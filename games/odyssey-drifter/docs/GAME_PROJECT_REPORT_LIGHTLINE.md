# 《光线之上》游戏立项报告 v1.0

项目 ID：`odyssey-drifter`  
当前阶段：Gate 1 与 Godot Tech Fit 已锁定；Gate 2 v1 被用户退回，正在制作 isometric v2  
目标平台：桌面浏览器  
文档日期：2026-09-03  
决策依据：用户从 A/B/C 三案中明确选择 C

## 1. 立项结论

建议立项。用户已将交付策略改为：**锁定 Godot，先完成 3–5 分钟可体验 Demo，由用户本人直测 Gate 2**；不批准直接制作 90–150 分钟完整游戏。

理由：C 同时具备可形成独特手感的动作语法、能与视觉共同生长的材料系统、能让 NPC 身体成为玩法信息的关系结构。它也是三案中技术与手感风险最高的一案。当前没有玩家证据证明“驭线”好玩，概念图也不是可玩性证据。

### 核心产品句

> 玩家在阿迦奔跑时，以一次按住—移动—随脚步松开的连续动作驭使承重光线；线形决定空间，张力决定运动，松开时机决定节拍。

### 立项边界

- **已批准**：概念 C、Godot 4.x、Windows 开发预览、桌面浏览器目标、NPC 阿迦、动态光线、呼吸式节奏、90–150 分钟的产品愿景。
- **待验证**：曲线手感、张力可读性、NPC 身体提示、确定性回溯、浏览器性能、触控板可用性。
- **未批准**：正式美术、四城区量产、完整对白、发行窗口与商业模式。

置信度：**低至中**。概念差异化仍成立，但用户直测已证明 v1 的目标、规则与环境因果不可读；只有 v2 复测后才能恢复对可玩性的信心。

## 2. 专家视角与设计原则

本报告采用最贴近问题的世界级创作者视角：**上田文人（Fumito Ueda）**，借用其“设计减法”思路和以角色依赖、空间动作建立关系的视角。审查问题不是“还能加什么”，而是：

1. 这个系统是否让玩家更能读懂阿迦？
2. 它是否改变光线的空间、张力或节拍？
3. 它是否让一次跨越产生准备—紧张—释放—停息？
4. 删除它以后，核心关系是否更清楚？

若前三问均否，删除。该视角用于推理，不代表本作要模仿具体作品的题材或美术。

## 3. 用户、场景与价值

### 目标玩家

- 18–35 岁，习惯桌面浏览器或 PC 独立游戏。
- 喜欢动作与情绪叙事结合，但不想阅读大量文本。
- 接受 90–150 分钟一次性完整体验，也愿意重玩短路线提高同步感。
- 对《ICO》《Journey》《GRIS》一类关系感或视听叙事可能有兴趣；这里只是受众参照，不是品质对标承诺。

### 玩家需求假设

玩家想要的不是更复杂的跑跳，而是“我的手势直接变成另一个角色可以感知和回应的物质”。该假设尚未验证。

### 产品价值

- 输入具有强视觉可传播性：玩家手势实时留下独一无二的运动轨迹。
- NPC 不是任务发放者，而是动作系统的另一半。
- 失败不是读档黑屏，而是把时间和光线一并收回，保持节奏连续。

## 4. 世界观

“退潮纪”后的城市失去了稳定地面。建筑并未坠毁，而是在一场永远未完成的呼吸里周期性分离、靠近、闭合。旧居民把这种现象叫“城市忘了如何呼气”。

余光是一种会记住牵引关系的物质：它不照亮物体，而是短暂显现物体之间曾经存在的路。只有移动中的人能让它承重，只有停下来的人能看见它保存的记忆。

阿迦携带一盏不再发光的旧灯，追逐城市最后一次完整黎明。他坚信自己一旦停下，就会像城区一样永远卡在半次呼吸里。玩家最初像无形的道路制造者，随后被阿迦通过脚步、回望和抓线承认为同行者。

世界规则必须服务玩法：

- 城市开合解释动态空间。
- 余光记忆解释曲线残影与回溯。
- 移动使光承重、停息使记忆显现，解释动作与叙事为何轮流发生。
- “最后黎明”提供方向，但最终被阿迦主动放弃，完成主题反转。

## 5. 角色：阿迦

### 人格核心

- **欲望**：赶上城市最后一次完整黎明，证明自己仍能继续前进。
- **恐惧**：一旦停下，就再也没有重新出发的能力。
- **习惯**：起跳前用脚尖轻敲光线两次；这既是自我安定，也是给玩家的暗号。
- **矛盾**：他用速度逃避记忆，却只能在玩家帮助他停下时真正面对记忆。
- **边界**：他会等待、质疑、抓线自救和拒绝危险路线，不能只是自动沿线移动。

### 八段弧线

1. **抢跑**：不等光线稳定就冲向断口，把玩家当工具。
2. **第一次等待**：在第一次回溯后主动放慢半拍。
3. **共同暗号**：脚尖两拍从自我习惯变成双方向沟通。
4. **主动自救**：路线失稳时抓住光线，不把所有失败压给玩家。
5. **选择慢路**：为看一件旧物主动放弃更快路线。
6. **三连同步**：连续三次跨越中，双方不需要文字提示。
7. **黎明前停下**：目标就在眼前，他却先停下，迫使玩家接受沉默。
8. **留下光**：不再追逐“最后一束”，而把共同织出的线留给后来者。

### 对白纪律

- 重要心理变化先由行为表达，再允许一句短对白确认。
- 不用谜语化独白解释世界设定。
- 不把焦虑写成“只要努力就能成功”。
- 单次停息对白不超过两句；阿迦可以保持沉默。

## 6. 核心玩法

### 唯一主动作：驭线

一次完整输入：**抓住光头 → 移动塑形 → 自动借锚 → 通过弧度调势 → 随阿迦脚步松开**。松开同时提交可承重曲线并发送光脉冲。

这不是四个技能。锚定由轨迹与空间关系产生；张弛由线形产生；脉冲由松开产生。辅助操作仅含取消、暂停、重开和无障碍输入模式。

### 三个耦合维度

- **线形是空间**：选择穿过哪个锚点，决定阿迦的路径与姿态。
- **张力是运动**：松线承接、稳线奔跑、紧线弹射，过载则断裂。
- **松开是节拍**：同一条线在不同身体相位释放，会成为支撑、摆荡或弹射。

### 25–45 秒循环

`预读 4–6 秒 → 驭线 7–12 秒 → 同行调势 8–15 秒 → 松开放势 2–4 秒 → 落点停息 6–10 秒`

高压连续时间不超过 15 秒。每次跨越后至少有 5 秒无需精准输入。停息不是奖励弹窗，而是玩家读取阿迦和世界的时间。

### 有意义的选择

至少两轮同时提供：

- 短、紧、释放窗口窄的直接路线。
- 长、松、窗口宽但经过记忆物的绕行路线。

两者都合法，不设置隐藏正确答案。选择改变动作风险、阿迦姿态和可见叙事，不改变善恶分数。

## 7. 操作与交互

### 默认输入

- 主键按住：抓取当前光头。
- 指针移动：塑形、借锚、调势。
- 主键松开：提交曲线并发送脉冲。
- 次键：取消尚未提交的曲线。
- `Esc`：暂停/继续。
- `R`：重开当前单局。

### 无障碍等价模式

第一次点击开始驭线，第二次点击释放；判定和风险与长按模式相同。提供减少动态、高对比、文字冗余、静音可玩和可选宽窗口。宽窗口若消除全部判断空间，则不是合格方案。

### 身体提示

阿迦以目光、胸腔、脚尖、重心和手臂给出空间目标、过紧、过松、释放窗口与失衡五类信息。每类必须同时有几何运动与至少一种声音/形状冗余；HUD 只能补充，不能成为主要玩法源。

## 8. 教程、失败与回溯

### 首次 30 秒

- 0–4 秒：阿迦看向唯一锚点，活动光头脉冲。
- 4–10 秒：他慢跑并轻敲脚尖，玩家开始拖线。
- 10–18 秒：曲线自动借锚，姿态和线形显示张力。
- 18–23 秒：阿迦再次两拍并压低重心，玩家松开。
- 23–30 秒：脉冲沿线传播，阿迦跨越并回望。

6 秒无输入才演示手势幽灵，12 秒无输入才出现一句具体文字。教程首次错拍不坠落，第二轮起取消保护。

### 失败

- 路线无效但阿迦仍安全：曲线收回，不计失败。
- 阿迦到达边缘仍无合法线：给约 250ms 明显失衡修正窗。
- 坠落或过载：记录明确原因，进入回溯。
- 同一节点连续三次失稳：进入完整失败画面，可立即以同种子重开。

### 回溯

保留最近 10 秒模拟缓冲，默认恢复到约 8 秒内最新合法安全快照；视觉表现压缩到 0.6–1.2 秒。没有合法快照时视为内容错误，不能猜一个位置。

## 9. 内容结构

### Gate 2：3–5 分钟

一条连续路线、五次跨越：平跨 → 低谷 → 单锚摆荡 → 双拍保持 → 双锚弹射 → 静息终台。灰盒结束时阿迦主动停下 4 秒，玩家不输入才成功。

### 完整产品：四区愿景

| 区域 | 呼吸相位 | 动作主题 | 阿迦变化 | 目标时长 |
|---|---|---|---|---:|
| 起风断层 | 吸气 | 承重、基础松放 | 从抢跑到第一次等待 | 20–30 分钟 |
| 悬压城区 | 屏息 | 移动锚点、长时间调势 | 建立脚尖暗号并主动自救 | 20–35 分钟 |
| 回声桥群 | 呼气 | 路线二选一、记忆慢路 | 愿意放弃最快路线 | 25–45 分钟 |
| 晨光终台 | 静止 | 三连同步、主动不输入 | 停下并留下光 | 25–40 分钟 |

总量为 90–150 分钟的当前底稿，但这只是内容估算，Gate 2 后必须用实际节奏重算。

## 10. 视觉方向

当前 C 概念图 `reframe-c-action-v1.png` 只证明构图方向可讨论，不是 StyleBible，也未通过 Gate 3。

### 原创性支点

- 光线不是霓虹装饰，而是有负载、惯性和记忆的“运动书法”。
- 城市不是普通废墟，而是以呼吸相位改变结构间距的巨型身体。
- 角色轮廓的重心、披挂和灯具变化承担玩法信息，不能被粒子特效遮住。
- 静息时才显现旧路和人类痕迹，形成“高速时简洁、停下时丰厚”的双层世界。

### Gate 3 前需由 visual-director 解决

- 三套以内的形状语言：城市骨架、余光曲线、角色轮廓。
- 三种以内的主材质及禁用材质。
- 可访问的张力状态，不以红绿或亮暗作为唯一差异。
- 关键帧四张：首次承重、单锚摆荡、双锚弹射、最终静息。
- UI、运动、灯光和后期令牌；负面提示词和资产生成提示词。

正式资产只能在 Gate 3 人工批准后生产。

## 11. 声音与动作方向

声音层级：足音是拍点，线鸣是张力，脉冲是释放，风声是呼吸。音乐不得持续覆盖这四层信息。

动作层级：准备姿态先于位移、重心先于结果、余波晚于落地。镜头在预读时说明空间，在放势时保留速度，在停息时重新容纳人物与世界；不追逐鼠标、不突然切轴、不用持续摇晃制造动感。

动作系统的最低可验证代理：头胸指向、脚尖双拍、后仰、前伸、压低、张臂失衡、落地肩沉。若必须依赖高质量成品动画玩家才读懂，Gate 2 失败。

## 12. 技术路线与能力需求

用户已直接锁定 **Godot 4.7.2 stable + GDScript + Compatibility renderer**。不再比较其他引擎；旧 Three.js 锁定不继承。Windows 用于快速开发预览，桌面浏览器仍是目标导出平台。

硬需求：

- 桌面浏览器受控 3D 空间投射和连续输入规范化。
- 确定性的动态曲线、锚点、张弛和角色运动。
- 6–10 秒可验证回溯；暂停冻结全部模拟相位。
- 角色姿态与曲线反馈同步，静音可玩且不依赖颜色。
- 状态机、重放、失焦、重复输入、恢复边界可自动测试。

敏捷实现必须暴露以下风险供用户体验：

1. 简化曲线模型是否既可读又有手感，无需通用绳索物理？
2. 鼠标与触控板在 30/60/144Hz 采样下能否得到等价判定？
3. 8 秒回溯的快照、重演和内存方案能否稳定？
4. 几何代理能否表达阿迦五类身体提示？
5. 目标设备 p95 帧时间能否不高于 20ms，输入反馈是否低于一帧？

## 13. 最低工程检查与 Gate 2

### 最低工程检查

- Godot 能解析工程并启动主场景。
- 程序化资产 ID、脚本和场景引用均可解析。
- 不把静态检查或开发者自测称作“玩法通过”。

### 用户本人直测

用户从标题开始体验并直接判断：

- 能否无需口头说明完成抓取、拖线、松开。
- 是否感知为一次连续动作。
- 是否能从阿迦身体提示调整线势或释放时机。
- 张紧—释放—停息是否成立。
- 阿迦是否像在配合，而不是沿线播放。
- 失败是否可解释。
- 五轮是否值得继续扩展。

只有用户明确回复批准，Gate 2 才通过；本阶段不要求五人样本，也不做自主乐趣评分。

## 14. 商业与发行假设

建议先按一次性短篇作品或免费序章验证，不在当前立项阶段决定定价、广告、内购或服务化。核心节奏与情绪叙事都与中断式商业化存在冲突；这是判断，不是市场事实。

可传播内容来自玩家独特曲线、失稳救回和三连同步片段，而非皮肤或数值成长。若后续需要商业验证，应先测试愿望单/试玩完成率，再谈完整产量。

## 16. 风险与对策

| 风险 | 概率 | 影响 | 先验证什么 | 失败时动作 |
|---|---|---|---|---|
| 驭线仍被感知为普通画线 | 中高 | 致命 | 用户是否感到张力节拍 | 缩减或重开概念，不加系统 |
| 输入过载/长按疲劳 | 中 | 高 | 鼠标与触控板、点击切换模式 | 调整单次时长和输入模式 |
| 张力判定不可解释 | 中高 | 致命 | 用户能否解释失败 | 改成确定性档位模型，拒绝隐藏吸附 |
| NPC 提示依赖成品动画 | 中 | 高 | 几何代理五类提示 | 简化提示或回到叙事非核心路线 |
| 浏览器性能不足 | 中 | 高 | 曲线+角色+回溯 p95 | 降低曲线自由度/快照粒度；仍超标则换路线 |
| 90–150 分钟内容重复 | 高 | 高 | Gate 2 后做 15–20 分钟耐久切片 | 缩短成 45–70 分钟完整作品 |
| 视觉压过玩法 | 中 | 中高 | 关闭特效仍能读懂状态 | 删除干扰特效，重做 StyleBible |

## 17. 停止条件

满足任一项，停止扩产并回到玩法规格或概念选择：

- 用户在两轮迭代后仍不认为驭线是一次连续动作。
- 用户认为失败主要来自延迟、随机或不透明判定。
- 用户只能盯 HUD，无法从阿迦身体获得有效信息。
- 需要自动路线吸附、自动释放或隐藏容错才能通过。
- 几何代理无法支持 NPC 提示，必须先做正式动画才知道是否成立。
- 最小曲线与回溯方案在目标设备仍持续超过 20ms p95 帧时间。
- 连续两轮在理解率、失败归因或节拍复述上无改善。

### 下一步唯一正确动作

直接实现 Godot 完整可体验 Demo，不修改旧 Web 灰盒冒充 C，也不让 visual-director 提前锁定美术。资产先按稳定 ID 和占位语义规划，用户试玩通过 Gate 2 后再统一细化。

## 19. 可验证、判断与残留分歧

### 可验证

- 用户已经选择 C。
- 当前 C 概念图已登记但未获视觉锁定。
- 旧技术证据验证的是旧静态铺路机制，不包含动态曲线、角色节拍或 8 秒回溯。
- 新玩法规格给出了完整状态、教程、暂停、失败、成功、重开与恢复边界。

### 判断

- C 是三案中最值得先做动作原型的一案，因为动作、视觉、NPC 和叙事可以围绕同一种材料耦合。
- 采用单次按住—移动—松开，比独立“画线键+脉冲键”更能保持身体连贯性。
- 90–150 分钟有明显内容重复风险，最可能在 Gate 2 后被下调。

### 信心不等于正确性

概念图的冲击力可能让我们高估玩法；对“有呼吸”的语言共识也可能掩盖实际输入只是拖拽。当前策略把判断权交给用户本人，因此首轮结论速度更快，但样本代表性更低；这个误差要在决定扩大生产前重新评估。

这是我认为我们仍然可能错的地方：玩家可能想要的是对光线本身的精密控制，而不是与阿迦建立关系；也可能相反。两者在概念阶段能共存，但生产优先级完全不同。Gate 2 必须记录玩家究竟关注“线”还是“人”，不能把两种反馈混成一个平均分。
