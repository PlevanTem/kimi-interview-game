# 《下一盏灯》体验规格 v1

状态：Gate 1 后、Tech Fit Lock 前。引擎、平台、设备映射、渲染和资产管线均未决定。

## 范围与目标

- 目标：在夜间高架步道上，用一条有限长度的灯带让旅者抵达当前可走的落点；连续完成 8 段，到达终点灯塔。
- 核心动词：**铺设**。取消、暂停、重开和观察调整均为辅助操作，不产生玩法结果。
- 时长：首段教程 0–30 秒；第 2–3 段约 45–75 秒；第 4–7 段约 90–180 秒；第 8 段收束 20–40 秒；完整一局 3–5 分钟。
- 内容预算：一个约 20×20 米可完整阅读的高架空间；3 类平台、3 类缝隙、4 类抽象环境意象、8 个固定路径布局种子。
- 禁止项：新增关卡、养成、经济、分支叙事、第二主动作、联网、运行时 AI、复杂物理，或将职业、收入、失业、疾病等现实困境用于奖惩。

## 交互意图与能力

| 意图 | 必需输入能力 | 结果 |
|---|---|---|
| 阅读下一段 | 指向或选择空间位置；可选小幅观察 | 看见起点、目标、当前可用长度 |
| 铺设 | 连续位置输入的开始、更新、结束 | 生成可实时预览的路径草案 |
| 放弃草案 | 取消 | 清除草案，不扣尝试 |
| 暂停 / 重开 | 离散系统操作 | 冻结并恢复，或回到同一种子初始状态 |

约束：起点锁定为旅者当前锚点；玩家只决定连续走向和终点。草案必须在世界内非文字化显示四种状态：可达、超长、未抵达目标、越出可铺区。不得要求仅靠颜色、反应速度、双击、长按强度或复杂手势完成；静态完整视图必须可完成全部段落。

## 核心循环与确定规则

`阅读断口 → 铺设预览灯带 → 判断有效性 → 提交 → 旅者通过 → 下一断口出现`

路径仅在以下全部成立时有效：

1. 从当前已点亮锚点开始；
2. 终点落入当前目标锚点的接受区；
3. 规范化折线路径长度不超过该段灯带预算；
4. 路径完全处于当前段允许的铺设带内。

不使用随机碰撞、动态物理、敌人、风、计分倍率或隐藏判定。旅者只沿预定义曲线匀速通过有效路径，不是第二个可控角色。

## 状态机

全局变量：`seedId`（固定布局）、`segmentIndex`（0–7）、`consecutiveExhaustions`（0–3）、`draftPath`、`pausedFrom`。

| 当前状态 | 事件与 Guard | Effect | 下一状态 |
|---|---|---|---|
| `Title` | 开始旅程 | 装载 `seedId`；归零进度和耗尽数 | `InitRun` |
| `InitRun` | 当前布局有效 | 建立首段锚点、目标、预算 | `TutorialObserve` |
| `TutorialObserve` / `Observe` | 从起点开始铺设 | 创建空草案 | `TutorialDraft` / `Draft` |
| `TutorialDraft` / `Draft` | 更新路径 | 固定间距重采样，实时显示有效性 | 原状态 |
| `TutorialDraft` / `Draft` | 取消草案 | 清空草案，不扣次数 | `TutorialObserve` / `Observe` |
| `TutorialDraft` / `Draft` | 提交有效路径 | 锁定路径 | `Traverse` |
| `TutorialDraft` / `Draft` | 提交无效路径 | 灯芯熄灭、耗尽数加一、清空草案 | `RecoverSegment` 或 `RunFailure` |
| `Traverse` | 旅者到达 | 路径化为星轨，意象清晰一次 | `ResolveSegment` |
| `ResolveSegment` | `segmentIndex < 7` | 进度加一、耗尽数归零、建立下一段 | `Observe` |
| `ResolveSegment` | `segmentIndex = 7` | 完整星轨、记录完成 | `RunSuccess` |
| `RecoverSegment` | 耗尽数小于 3 | 同一布局、目标、预算恢复 | `Observe` |
| `RunFailure` / `RunSuccess` | 再走一次或立即重开 | 用相同 `seedId` 重新初始化 | `InitRun` |
| 任意非结束状态 | 暂停 | 保存 `pausedFrom`，冻结输入与演出 | `Paused` |
| `Paused` | 继续 | 原样恢复草案或旅者进度 | `pausedFrom` |
| 任意状态 | 非法事件 | 无状态变化，只记录诊断 | 原状态 |

失败定义：一次无效提交耗尽一次灯芯并回到同一段；连续三次耗尽进入 `RunFailure`。提示只说明“这条灯带没有抵达落点。再试一次。”；不得写成个人能力或人生判断。失败界面直接重开，不等待、不羞辱、不锁内容。

确定性要求：同一 `seedId`、段号和输入路径点列必须产生相同有效性、消耗数、旅者轨迹及结果。判定前固定重采样和精度简化，不能因帧率或采样频率改变。暂停保留草案点列、预算和旅者进度；取消和非法事件永不消耗灯芯；重开清空全部运行变量。测试运行应导出 `seedId / segment / input points / validity / transition / timestamp` 以供重放。

## 前 30 秒教程

| 时间 | 行动与反馈 |
|---|---|
| 0–4 秒 | 起点与目标锚点已亮，短句“点亮下一百米”。 |
| 4–7 秒 | 无输入的幽灵路径从起点到目标短暂演示后消失。 |
| 7–15 秒 | 提示“从亮点铺到前方落点”；玩家绘制草案并立即看见其有效性。 |
| 15–24 秒 | 有效提交后旅者通过，建立“铺设导致前进”的因果。 |
| 24–30 秒 | 下一段出现，移除分步提示，仅保留必要 HUD。 |

玩家 6 秒未行动时重放无文字演示；12 秒仍未行动才显示文字提示。教程不另建训练关，不强迫玩家先犯错。

## 信息与反馈

优先级：世界内起点、目标、草案与有效性；其次是可用长度和单一错误原因；再其次为段进度、连续耗尽数与暂停/重开；最后才是星轨和抽象意象。

| 情况 | 即时反馈 | 禁止 |
|---|---|---|
| 有效草案 | 路径稳定、目标确认、剩余长度可读 | 仅用颜色表达有效性 |
| 超预算 | 超限端点与预算明确显示 | 提交后才告诉玩家失败 |
| 未抵达 / 越界 | 违规点可见，给出唯一错误原因 | 把多种错误合成笼统“失败” |
| 段成功 | 灯带点亮、旅者通过、星轨留下 | 以分数或效率评价人生选择 |
| 一次耗尽 | 短熄灭、立即回到同段 | 长动画、羞辱性文案、丢失已完成段 |

无障碍：状态用形状、图标和文字冗余表达；可调文字、对比度、非必要运动；提供不依赖长按精度的等价确认方式。

## 灰盒验收与 Gate 2 证据

| 场景 | 通过条件 |
|---|---|
| 首次理解 | 5 名新手中至少 4 名在 30 秒内首次铺至可达终点。 |
| 有效路径 | 只发生一次 `Traverse`，旅者抵达，段进度加一。 |
| 无效恢复 | 第一次只耗尽一次并回到同段；下一次有效路径可通过。 |
| 三次连续耗尽 | 恰在第三次进入 `RunFailure`，可立即同种子重开。 |
| 暂停恢复 | 在草案和旅者通过中暂停、继续，状态逐项一致。 |
| 全程成功 | 8 段后且仅在第 8 段后进入 `RunSuccess`。 |
| 非法事件 | 注入不允许事件，状态与计数不变且有诊断。 |
| 确定性重放 | 同一种子与轨迹重放两次，转移、消耗和结果相同。 |
| 主题可读性 | 5 名玩家中至少 3 名能描述一次有意义空间选择，而非仅“画线”。 |

Gate 2 仍被阻塞。届时必须提供：可重复的 8 段灰盒、状态场景结果、固定种子重放、5 名新手原始测试记录、完整成功与失败重开的视频或交互证据、以及每个缺陷的“问题→证据→根因→最小修改→验证→前后结果”账本。

## 风险与止损

| 风险 | 拒绝信号 | 最小修正 |
|---|---|---|
| 退化为普通连线 | 玩家说“只是连线” | 调整断口、预算与结果反馈；不加系统 |
| 判定不透明 | 首段停留超过 20 秒，失败归因界面 | 强化预览、单一错误提示、扩大首段接受区 |
| 重试像惩罚 | 两次失误后退出 | 缩短反馈、即时同段恢复、降低早段跨度 |
| 过早重复 | 第 3 段前已预测全部布局 | 仅改空间关系与曲率，不加规则 |
| 主题失真 | 感到说教、评判或消费困境 | 删除对应文本/意象，回到“下一段可走” |
