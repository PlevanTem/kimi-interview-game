# 《千名之海》主角 Three.js 程序化模型 v1

状态：Graybox / Previsual code model。Gate 2 与 Gate 3 仍未通过。

## 方法

采用游戏动画师 Jonathan Cooper 的“规则状态与动画表现分离、关键姿势优先、战斗距离剪影可读”视角。四视图决定稳定身份与部件比例；动作表只决定动作语义和受力方向。代码不得从单张渲染图臆造拓扑、UV 或蒙皮质量。

## 不可漂移锚点

| 层 | 四视图要求 | 代码实现策略 |
|---|---|---|
| 比例 | 约 4.5 头身、头大肩窄、手脚略放大 | 以脚底中心为原点，头/胸/骨盆/四肢使用独立 pivot |
| 轮廓 | 黑色块面发束、宽兜帽、高领披风、右后方赭金尾带 | 发束、兜帽、三片披风和尾带独立几何，不靠纹理假轮廓 |
| 配色 | 黑发、暖棕肤色、深海青披风、盐白内衫、赭金边、深褐护具 | 少量共享哑光材质；金属仅用于扣具和桨刃局部 |
| 服装 | 胸前菱形扣、几何披风边纹、腰带包、分段护臂、灯笼裤、分层靴 | 每类作为可替换 group；装饰用浅浮雕几何而非高分辨率贴图 |
| 装备 | 短柄桨刃、浅色刃体、青色嵌芯 | 武器独立 pivot；攻击姿势和拖尾不改变规则命中 |
| 表情 | 大棕眼、粗黑眉、严肃但非凶狠 | 眼、瞳、眉独立；受击动作只改变姿势和表情，不改变身份 |

## 组件契约

- `HeroCharacterModel`：主模型，提供动作、身份色、线框、关节标记、武器拖尾与缩放参数。
- `HERO_LAB_ACTIONS`：12 个调试动作的唯一 UI 清单。
- `HeroModel`：现有游戏适配器，继续接受 reducer 的 `ActionName`，不让视觉状态写回规则。
- 世界坐标：Y 轴向上，脚底中心为模型原点；主游戏继续由 `PlayerRig` 决定移动、面向和镜头。

## 调试入口

浏览器地址：`/?lab=character`

调试页必须支持：OrbitControls、正/左/背/四分之三视角、12 动作切换、自动轮播、暂停、线框、关节标记、武器拖尾、参考图对照和 Three.js draw calls / triangles / geometries 统计。

## 真实边界

- 这是用基本几何重建的可运行代码模型，不是从图片自动恢复出的精确网格。
- 动作是 pivot 驱动的姿势插值，不是骨骼蒙皮动画；可用于验证比例、穿模和动作读性。
- 正式模型仍需要 DCC 中完成拓扑、法线、UV、绑定、权重、动画 clips、碰撞代理与 LOD，并通过 Gate 3 后才能替换为生产资产。

## 评测顺序

1. 在四视角确认轮廓、装备和披风分层。
2. 逐个切换动作，检查脚底锚点、武器路径、披风穿模和身体体积是否漂移。
3. 在线框与关节模式检查部件层级。
4. 回到主游戏战斗镜头检查实际屏幕占比与招式可读性。
5. 记录 draw calls / triangles，再决定是否合并静态部件或转 GLB。
