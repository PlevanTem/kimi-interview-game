# 《千名之海》DESIGN v1 — 盐岬港验证切片

> 状态：Gate 1 已由用户锁定；引擎无关玩法规格完成；等待 Tech Fit Lock。本文不是技术方案，也不是正式 StyleBible。

## 结论

首个 Demo 不做“小型奥德赛”，只回答一个决定产品生死的问题：

> **玩家能否把身份当成可构造、可验证、能改变空间权限且会留下传闻的系统，而不是对话树里的钥匙颜色？**

若答案是否定的，完整群岛、航海、战斗和正式美术都不值得继续投资。

## 专家框架

主框架采用 Harvey Smith 与 Raphael Colantonio 对《Dishonored》的描述：一致、连贯的系统和世界设定，应允许玩家即兴组合并形成自己的解决方案。盐岬港因此只规定角色目标、物理空间和事实规则，不为玩家预写唯一路线。[GDC 原始页面](https://www.gdcvault.com/play/1019078/Empowering-the-Player-in-a)

环境叙事采用 Harvey Smith 与 Matthias Worch 的问题：玩家应该主动从空间和道具中推断“这里发生过什么”，系统还应让环境对玩家行动作出反应。[GDC 原始页面](https://www.gdcvault.com/play/1012647/What-Happened-Here-Environmental)

### 反驳

“多路径”不等于摆三扇门，“NPC 有 AI”也不等于世界有灵魂。若门、人物和证据不共享规则，所谓自由只是三条昂贵的脚本。盐岬港只保留四类长期事实：`身份声明`、`证据`、`款待/关系`、`见证记忆`。每一类都必须改变玩家下一步能做什么。

## 完整产品到 Demo 的映射

| 完整产品支柱 | Demo 中真实实现 | Demo 中模拟 | 暂不实现 |
|---|---|---|---|
| 身份改变权限与风险 | 两种身份、派生通行权、盘问与矛盾 | 身份在下一岛的后果预览 | 大规模身份履历 |
| 款待和关系是社会规则 | 执政官欠下的旧客债、神庙净礼、码头互助 | 一条港外关系结果 | 多岛关系网 |
| 世界记住有限事实 | 四项事实、五名关键角色、一个移动见证者 | 离港传闻包 | 完整传播网络 |
| 玩家组合系统解决问题 | 观察、交涉、赠礼、潜行、布置、等待 | 冲突用简化阻挡表达 | 完整战斗系统 |
| 归乡读取旅程证据 | 结尾展示下一岛将相信和怀疑什么 | 一张归乡证据卡 | 伊萨卡终局 |

Demo 不能证明完整游戏的内容耐久度、多岛状态规模、战斗平衡、长期船员弧或商业可行性。

## 场景：盐岬港

执政官墨兰提俄斯以“缺少合法船印”为由扣押玩家的船“归潮号”。太阳落下前，潮门将封闭；歌者兼信使伊翁也会搭另一艘商船离开，把他相信的版本带往下一座岛。

玩家必须：

1. 取得船印。
2. 打开潮门。
3. 登上归潮号。
4. 决定伊翁将带走哪一版身份。

### 空间母版

港口不是平面任务大厅，而是一组三层相互可见的社会门槛：

- **下层码头**：归潮号、修船台、潮门和工头多萝；开放但受守卫视线控制。
- **中层集市/酒馆**：伊翁收集传闻，船员斐弥俄斯被看守；人物与信息交换最密集。
- **上层执政厅/海神庙**：两个身份分别获得的正式入口；地下水道把神庙与潮门背面相连。

玩家从入口能同时看见被扣船、上层两座权力建筑以及正在移动的伊翁。目标、权力和时间压力必须由世界构图表达，不靠任务箭头解释。

## 两个身份

### 特洛伊归来的船长

- 权限：进入执政厅外院、正式申诉归潮号、命令己方船员。
- 风险：必须解释缺失王印、不一致口供和被认定为海神祭品的货物。
- 玩法倾向：公开关系、款待债、交涉和证据对质。

### 风暴后的无名朝圣者

- 权限：进入海神庙、接受净礼、接近潮门地下水道。
- 风险：不能携带武器或贵重信物；指挥船员或持有船印会暴露矛盾。
- 玩法倾向：仪式、潜行、环境通路和身份遮蔽。

身份不能在菜单中无成本切换。改变公开身份必须找到能见证新版本的社会场合，并处理已经知道旧版本的人。

## 四项可验证事实

| 事实 | 谁持有或知道 | 支持什么 | 同时造成什么风险 |
|---|---|---|---|
| 桨疤 | 玩家、斐弥俄斯 | 老船长经历 | 暴露海战与真实年龄 |
| 断裂客符 | 执政官、港务档案 | 墨兰提俄斯家族欠玩家客债 | 公开后会让他转为敌对主人 |
| 神庙盐痕 | 朝圣袍、塔勒娅 | 朝圣者完成净礼 | 可被洗掉、转移或识破伪造 |
| 隐藏船印 | 没收货箱、伊翁的见闻 | 打开潮门并证明与船的关系 | 朝圣者持有会形成直接矛盾 |

事实有四种状态：`未知`、`玩家已知`、`某人记得`、`公开传播定论`。物品是否在玩家背包不是唯一真相来源；NPC 记忆与公开状态必须分开。

## NPC 不是聊天终端

| NPC | 当前目标 | 日 | 可被玩家改变的条件 |
|---|---|---|---|
| 墨兰提俄斯 | 保住扣船收益并维持主人合法性 | 宴席 → 码头验货 → 日落封印 | 客债公开、神庙反对、码头罢工 |
| 塔勒娅 | 追回失踪祭礼并掌控潮门 | 神庙 → 潮门祝祷 → 收祭 | 祭礼去向、净礼身份、执政官亵渎证据 |
| 多萝 | 重开港口并削弱垄断 | 修船 → 仓库争执 → 罢工 | 工钱、潮门控制、船员帮助 |
| 伊翁 | 收集最可信且最好传唱的版本 | 集市 → 酒馆求证 → 登船 | 亲眼所见、两人以上一致口供、玩家贿赂或救助 |
| 斐弥俄斯 | 获释并找到酒 | 被看守 → 可获释 → 酒馆 | 玩家命令、赠酒、害怕执政官 |

NPC 使用有限状态、日程、感知和事实比较，不使用生成式 AI 决定规则结果。对白可以变化，但权限和后果必须由可检查状态产生。

## 可形成的解法，不是预写路线

- 公开旧客债，迫使执政官以主人身份交还船印。
- 以朝圣者身份进入地下水道，从潮门背面开门并潜入货仓。
- 证明执政官侵吞神庙祭礼，引发神庙与码头联合施压。
- 救出斐弥俄斯，让其支持船长身份；也可以隐藏或破坏他的口供。
- 操作伊翁的见闻，让当前谎言成为下一岛的优势，同时接受一项后续风险。

关卡不检查“玩家走了路线 A/B/C”，只检查最终状态：`船印`、`潮门`、`拘押状态`、`关系介入`和`传闻包`。

## 状态循环

`抵达观察 → 门槛声明 → 自由计划 → 被盘问/处理矛盾 → 船只就绪 → 伊翁离港 → 成功或失败 → 重开`。

必须可达：开始、教程、游玩、暂停、继续、成功、失败、重开和非法事件恢复。完整转换表、Guard 与 Effect 见 `context/gameplay-sea-of-thousand-names-v1.json`。

非法事件不得偷偷修改世界：例如在暂停状态取得物品、同一事实被重复公开、已离港的伊翁获得新记忆。系统应忽略事件并记录诊断码。

## 教程：一次只教一条因果

1. **先观察**：时间暂停，玩家安全看到断裂客符和被扣船，理解环境里有事实。
2. **再声明**：跨过港门时选择身份，同时看到一项权限和一项已知弱点。
3. **第一次盘问可撤回**：守门人只核对玩家已经看见的事实，不因第一次错误立即失败。
4. **让见证者在眼前学习**：伊翁复述刚听到的关键词，并改变行走目标。
5. **第一次系统组合不标答案**：同一仓库入口允许用赠礼、潜行或转移关系解决。

不使用长教程框、正确答案高亮和隐藏信任百分比。

## 信息与反馈

优先级从高到低：物理目标 → 当前身份/权限 → 眼前矛盾 → 伊翁即将传播的事实 → 日落阶段 → 完整事实日志。

- 获得权限时，NPC 必须在世界中让路、开门或改变站位；UI 只补充权限来源。
- 发现矛盾时，NPC 看向证据载体，两项冲突事实并排出现；不显示抽象“怀疑 +10”。
- 伊翁学到事实时，他复述关键词并改变下一目的地，日志记录来源。
- 失败时，镜头和动作指向导致失败的人、门或潮门；只给一条原因。
- 成功时展示下一岛“将相信什么/将怀疑什么”，证明传闻同时是奖励和债务。

## 可编辑插槽与母版锚点

### AI 可以修改

- 身份、证据、传闻和角色日程的数据条目。
- 遭遇数值、日落阶段长度和感知参数。
- 经资产注册表解析的模型、材质、动画、声音和字体。
- StyleBible 锁定后的语义令牌值。
- 不改变事件契约的局部岛屿规则模块。

### 未经 Gate 不得修改

- 身份必须同时产生权限和风险。
- 事实的来源、持有人、公开状态和记忆必须可追溯。
- 成功/失败与 RumorPacket 的事件契约。
- 固定种子、重置语义和黄金检查点。
- 相机尺度、交互距离和视觉语义母版。
- 资产 ID、许可证和来源记录。

每次重要修改写入迭代账本；Gate 前保存可恢复提交或标签。连续两轮没有改善就回退，不叠补丁。

## Demo 验收

### 功能验收

- 两种身份确实改变不同入口、动作和盘问风险。
- 四项事实均有来源、持有人和至少一次可观察状态变化。
- 伊翁按日程移动、学习有限事实并生成可读 RumorPacket。
- 至少两种不同系统组合可以完成船印与潮门目标。
- 开始、暂停、继续、成功、失败和确定性重开全部可复现。

### Gate 2 人工问题

1. 声明身份前，你是否主动观察过环境或人物？
2. 你能否说清当前身份给了什么权限，又暴露了什么弱点？
3. 你是否知道伊翁现在相信什么、为什么相信，以及他何时离港？
4. 你的解决方案是自己形成的，还是在寻找设计者给出的正确选项？
5. 失败时能否指出是哪两项事实冲突，或哪个关系没有介入？
6. 你是否愿意换一个身份重试，并预期行动空间会变化？
7. 核心机制是否值得进入正式视觉设计？

Gate 2 仍由用户批准。工程测试、截图和自评不能替代实际体验判断。

## 技术能力需求，不是技术选择

- 风格化 3D、多入口港口、基础导航和遮挡。
- 五名关键 NPC 的有限日程、感知和可中断交互。
- 数据驱动的身份、事实、权限、关系和传闻规则。
- 可序列化、可检查、可确定性重置的纯玩法状态。
- 上下文交互和潜行可见性；首个 Demo 不要求完整战斗。
- 稳定资产 ID、许可证和替换槽。
- 自动状态测试、固定检查点截图和运行日志。

目前仍缺少会实质影响 Tech Fit 的信息：最终交付是 Windows 下载版、浏览器链接，还是两者都要。镜头也应在技术 spike 中比较第一人称、近距第三人称和斜俯视的社会线索可读性与资产成本，而不是凭现有仓库决定。

## 置信度与风险

- **高置信度**：身份必须改变权限与风险；否则概念不成立。
- **中置信度**：一个港口足以证伪该假设，但不能证明多岛耐久度。
- **低置信度**：当前还无法判断最佳镜头、引擎和完整制作成本。

这是我认为你仍然可能错的地方：工作室级品质不是更密的资产和更长的 Wiki。真正的品质锚点是玩家能否看见规则、形成计划、预测结果，并在失败后准确解释发生了什么。若这四点没有成立，精美场景只会让错误方向更昂贵。
