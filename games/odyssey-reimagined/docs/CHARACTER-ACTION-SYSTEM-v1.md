# 《千名之海》主角动作系统 v1

状态：Graybox 动作审计 + Previsual 关键姿势定义。本文不构成 Gate 3 视觉批准，也不把单张动作表误称为可播放动画。

## 判断框架

采用游戏动画师 Jonathan Cooper 的游戏动画视角：先把规则状态与动画表现分开，再用清楚的预备、接触、恢复和剪影读性定义关键姿势。核心标准不是姿势数量，而是玩家能否在战斗距离内预判承诺、辨认有效帧，并看出动作何时重新可控。

## 当前动作系统审计

| 表格槽位 | 动作 / 建议状态 ID | 输入或触发 | 规则层现状 | 当前 3D 表现 | 本次关键姿势 | 后续可播放动画要求 |
|---:|---|---|---|---|---|---|

| 03 | 行走 `locomotion_walk` | WASD / 方向键 | 已实现：相机相对移动、加减速、边界约束 | 部分实现：移动时仍只有通用腿部微摆 | 接触步，前脚脚跟落地 | 四相位循环；底部中心锚点；消除脚滑 |

| 06 | 轻击一 `light_1` | 左键 / J | 已实现：通用 `light` 使守势 -1 | 已实现单一桨刃摆动 | 对角快速斩，低承诺 | 有效帧目标 120 ms；短恢复；可接续第二击 |

## 未被这张 12 格图掩盖的缺口

| 缺口 | 事实 | 决策 |
|---|---|---|
| 轻击三 | DESIGN v2 写了三段连击，代码只有一个 `light` 状态 | 先补 comboIndex、输入缓存和第三击规则，再产第三击关键姿势 |
| 跳跃 / 攀越 | 旧动作表包含，但当前关卡、输入和状态机均未实现 | 不占本轮图格；等关卡确实需要垂直移动再立项 |
| 死亡 / 倒地 | 当前失败由 `hit` 后切 UI 状态，没有独立角色动作 | Gate 2 若要求失败可读性，再补独立失败姿势和镜头 |
| 逐帧播放 | 本次输出是 12 个语义关键姿势，不是动画帧序列 | 需骨骼、时间轴、共享根骨、脚底锚点和引擎内循环验证后才可称动画资产 |

## Spritesheet 读取顺序

画布为精确 9:16、3 列 × 4 行，按左到右、上到下读取：

`idle_neutral → idle_combat → locomotion_walk → locomotion_run → observe → light_1 → light_2 → heavy → dodge → parry → hit → namebreak`

角色一致性锚点：4.5 头身 Q 版比例、黑色块面发束、深青兜帽披风、赭金包边与大几何纹、象牙色内衫、深色灯笼裤、棕色护臂/靴、短柄桨刃。任何正式模型替换都必须先保住轮廓、配色角色和装备识别，再增加细节。

## 验收边界

- 本图可用于确认动作语义、剪影、披风受力方向和武器路线。
- 本图不可用于宣称帧数、节奏、根运动、无敌窗、命中帧或蒙皮质量已经完成。
- 最小下一步是把 01、02、03、05、06、08、09、10、11、12 制成同一骨骼的灰盒 clips，并在真实战斗镜头下检查脚滑、武器穿模与输入响应。
