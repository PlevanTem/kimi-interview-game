# 3–5 分钟约束审计

## 结论

**是，它已经成为限制创意与玩法策划的直接依据，而且影响足以使旧排序失效。** 问题不在于短 Demo；问题在于流程把 Demo 的交付边界提升成了完整游戏的定义、淘汰标准和评分优势。

置信度：高。证据来自当前技能、代理提示词、GameBrief、IDEATION 淘汰理由、候选内容预算和验证器的直接文本，不依赖主观回忆。

## 影响判断

### 1. 对 IDEATION：高影响

- 开放航程、章节探索、船员关系、长期代价积累、身份伪装网络和多岛屿系统，在判断“是否值得成为完整游戏”前就因 Demo 成本被降级。
- “奥德赛不该是航海 RPG”被表达得过于绝对。更准确的判断应是：**航海 RPG 不能只靠题材成立，但可以在拥有独特系统命题时成为有效候选。**
- Roguelite 与漫长归途、反复失败、神祇干预、记忆性世界之间本来存在结构适配；旧流程没有评估这种产品潜力，只评估了它是否塞得进短切片。

### 2. 对 DISCOVER：低至中影响

- 原始来源、奖项事实以及战斗、关卡、动画、AI 的一般方法仍有效。
- 受影响的是“对本项目的转译”：旧笔记经常把行业方法压回单场景、少状态和短时长。这些转译必须在新候选出现后重新映射。

### 3. 对 DEFINE 与排序：高影响

- 三案都是围绕“一项立刻可灰盒的动作”设计，而不是从完整游戏的长期吸引力、宏观循环和内容扩展能力出发。
- 原评分中 `feasibility` 占 30%，`scopeSafety` 占 10%。在固定短 Demo 前提下，40% 权重会系统性奖励更小、更易实现的概念。
- 《无人呼救》88.9 分只能说明它是三个受限切片中最易形成清晰因果的一案，不能说明它是最值得制作的完整游戏。

## 判断与未知

- 旧三案不因此自动变差；它们仍可成为完整游戏中的关卡、Boss、章节或系统种子。
- 无法确认放宽后哪种完整游戏方向最佳，因为尚未重新进行不受该约束影响的 IDEATION。这是未知，不应用旧排名填补。
- 新一轮必须先评价产品潜力，再把 Demo 可验证性作为风险信息；两者不能合并成一个“越小越高分”的总分。

## 已执行修正

1. 在 `AGENTS.md` 中明确完整游戏愿景与 Demo 验证切片的边界。
2. 删除 `game-concept-forge`、`vertical-slice-design` 和 `concept-director` 中统一 3–5 分钟、单场景、单动词的完整产品限制。
3. `GameBrief` schema 不再强制 `sessionMinutes`；旧历史文件仍兼容。
4. 新建 `brief-odyssey-reimagined-v2`，分别记录 `fullGameVision` 与 `demoValidation`。
5. 旧三案、旧排名和旧 Gate 1 审阅包标记为 `superseded_by_rescope`，active Gate 1 退回 `not_started`。

## 下一轮判定原则

- 先问：如果有足够制作资源，这个完整游戏是否有独特、可持续的玩家体验？
- 再问：决定它生死的最高风险假设是什么？
- 最后问：取得该证据的最小 Demo 是什么？它可以很短，也可以超过五分钟；它不需要代表完整内容量。

这是我认为你仍然可能错的地方：取消时长上限不等于取消范围纪律。如果新一轮把“完整愿景可以很大”误解为“第一个 Demo 也要同时实现航海、战斗、成长、伙伴与叙事”，会从过度收缩滑向不可验证的过度扩张。正确边界是产品愿景开放、单次实验收敛。
